# Changelog

## 0.4.2
- Fixes from the first days of real P&ID markup work (the team's own lessons, recorded in the learning inbox):
  - `pdf_find` / `find` in `pdf_markup` matched pieces of words and across word breaks (a search for `DP` also marked `APD PRD` and `AND PROVIDED`). Searches now match WHOLE words (a hyphen is part of a tag); `contains: true` allows part of a word; several labels can be looked up at once (`PSV-512F|PSV-512G`).
  - Comment text with degree, squared, cubed or plus-minus signs showed `?`; they are now drawn (Latin-1), and characters the font cannot show are reported in the warnings.
  - A yellow legend line was unreadable (yellow on white): it is now black on a yellow band.
  - The leader arrow of an automatically placed comment could cross other comments in a crowded zone, or run across the sheet: it never crosses another comment, cloud or arrow now and stays short; when no such place exists the comment is NOT written and the warning says to give `at`.
  - Replacing a QC-Markup file the tool wrote itself no longer asks for approval each time (other files still do).
  - New item type `strikeout` (a line through the wrong text; the comment beside it says what replaces it); `px` boxes measured on a picture need no `in.rect` (the whole displayed page is the default); `at` is documented as the bottom left corner of the box.
  - `pid_compare` lists the first 80 problems and counts the rest per sheet (a full sheet gave over 100,000 characters), and checks first whether the two files look like a pair (`pair`).
- Skill `qc-pid-markup` rewritten with the same lessons: pair the files and look at both overviews before the text comparison, a hand-marked original (red = new value, struck = deleted) is incorporated in the redraw, read codes character by character, the team's short comment style (`UPDATE SCALE TO NTS`), how to resume after a usage limit.

## 0.4.1
- Trained on the real client sheets (A3 scans of hand-marked P&IDs and our A0 redraws): drawings are now checked **by the sheet's own grid zones, never by arbitrary cuts**. New tool `pdf_zones` reads the real page size (A0-A4, either orientation), finds the sheet's own border grid from its tick marks (ISO 5457 grid if there are none) and gives review tiles with the zoom that suits the sheet size (a scan is never rendered above its own resolution); the same tiles can be forced on both drawings of a pair, so tile T2.2 of an A3 scan and of an A0 redraw is the same part of the drawing.
- Markup: works on rotated pages (as the client files are), marks are scaled to the sheet size (an A0 comment is as readable as an A3 one), comment boxes avoid the drawing's lines on real sheets, text is found on rotated pages, and an item can be given as a box measured on a tile picture (`in` + `px`) for sheets that have no text layer (scans, text drawn as lines).
- Skill `qc-pid-markup` learned how the real sheets look (scan against vector, markup colours, covers and lists of drawings in front, pairing by drawing number, office comment style, comment lists per area).

## 0.4.0
- P&ID QC with a markup PDF, trained on the QC lead's own working prompt: the user gives the client's RAW P&ID and our redraw (OUTPUT) and Claude finds RAW and OUTPUT itself, takes the drawing number from the title block, checks zone by zone (client markups, text and data, every flow arrow, symbols and line types, overlaps, spelling, additions, errors in the raw) and writes `<drawing number>_QC-Markup.pdf`: a cloud at every error with a small boxed comment and leader arrow beside it, yellow highlights on what was updated as per client markup, a legend with a green OK line. New skill `qc-pid-markup`.
- New tools: `pdf_markup` (real editable annotations for Bluebeam / Acrobat: revision clouds, highlights, boxed comments with leader arrows, legend; comment boxes are placed automatically in free space, not on text, linework or each other; the drawing itself is never changed), `pdf_find` (where a text is on a page, exact box) and `pdf_render` (a page or a zone as a picture at high zoom, so Claude can look at the drawing and at its own markup).

## 0.3.1
- Fix: an automatic update failed with "The process cannot access the file ...\mcp\Pec.Qc.Mcp.exe because it is being used by another process" whenever a Claude Code or Claude Desktop session was still running the MCP server. Setup now moves a locked file aside (Windows allows renaming a running program), puts the new one in place and removes the leftover later; the running session is not killed and keeps the old copy until it restarts.

New tools `harness_guide`, `harness_find`, `harness_install`, `harness_skill`, `harness_run`, `harness_test`, `harness_publish`; skill `qc-cli-anything`. Harnesses run in a private Python environment (uv); every run is approved by the user.

## 0.2.0
- MCP servers for the Autodesk programs are installed by the program itself, not by the vendors' scripts: no console window, no questions. Settings has an "Install MCP servers..." button (AutoCAD, Plant 3D, Civil 3D, Navisworks with NavisCoord, Revit; each shows whether the program is on this PC and whether its server is installed, with Install / Reinstall and "Install all"); Setup offers the same list. Each server is downloaded from its publisher, checked against the published SHA-256, installed (plug-in and server), tested with a real MCP handshake and connected to Claude Desktop; installed servers are also available in the assistant's own chat.
- UI: icons and the ellipsis, bullet and dash characters showed as empty boxes and as garbled letters (text saved with the wrong encoding since Phase 9): repaired in four files and a test now fails if any source file contains such text; chat bubbles follow the width of the window (a reply uses the room available, a user message up to three quarters of it) and re-wrap when the window is resized.
- DWG files are read by a reader built into the product (no AutoCAD needed); AutoCAD's console is only a fallback.
- P&ID and GA checks accept DXF and DWG drawings as well as PDFs.
- CAD files: `cad_read` reads DXF (texts, attributes, layers, counts, line lengths) and DWG (converted through AutoCAD's console on a copy); NWD attachments are exported with model_export; skill `qc-engineer-mindset` (plan any task, open everything attached, cross-check, say what was not checked).
- Script tools: when nothing does what the user asks, Claude writes a small C# tool, tests it, and publishes it for the QC lead's review; once approved every colleague can use it. By default the author's approval shares the tool at once and a tool may use any .NET library; settings `ScriptReview` = `lead` and `ScriptSandbox` = `strict` restore lead review and the sandbox rules. Tools run in a separate process with a time limit and are pinned by SHA-256. New tools `script_tool_find`, `script_tool_draft`, `script_tool_run`, `script_tool_publish`, `script_tool_pending`, `script_tool_review`; skill `qc-tool-building`. The MCP server is now shipped as a folder instead of one file.
- Phase 11 (pilot kit): finding_feedback, pilot_time, pilot_metrics and pilot_compare (the assistant's saved report against the QC team's own hand list), install results logged by Setup, pilot plan, rollout procedure and a hand-list template.
