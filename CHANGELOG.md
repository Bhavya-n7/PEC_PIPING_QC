# Changelog

## 0.1.0 - first release candidate (Phases 0-4)
- UI: icons and the ellipsis / bullet / dash characters showed as empty boxes and as "runningâ€¦" (text saved with the wrong encoding since Phase 9): repaired in four files and a test now fails if any source file contains such text; chat bubbles follow the width of the window (a reply uses the room available, a user message up to three quarters of it) and re-wrap when the window is resized.
- DWG files are read by a reader built into the product (no AutoCAD needed); AutoCAD's console is only a fallback.
- P&ID and GA checks accept DXF and DWG drawings as well as PDFs.
- CAD files: `cad_read` reads DXF (texts, attributes, layers, counts, line lengths) and DWG (converted through AutoCAD's console on a copy); NWD attachments are exported with model_export; skill `qc-engineer-mindset` (plan any task, open everything attached, cross-check, say what was not checked).
- Script tools: when nothing does what the user asks, Claude writes a small C# tool, tests it, and publishes it for the QC lead's review; once approved every colleague can use it. By default the author's approval shares the tool at once and a tool may use any .NET library; settings `ScriptReview` = `lead` and `ScriptSandbox` = `strict` restore lead review and the sandbox rules. Tools run in a separate process with a time limit and are pinned by SHA-256. New tools `script_tool_find`, `script_tool_draft`, `script_tool_run`, `script_tool_publish`, `script_tool_pending`, `script_tool_review`; skill `qc-tool-building`. The MCP server is now shipped as a folder instead of one file.
- Phase 11 (pilot kit): finding_feedback, pilot_time, pilot_metrics and pilot_compare (the assistant's saved report against the QC team's own hand list), install results logged by Setup, pilot plan, rollout procedure and a hand-list template.
- Setup offers the MCP servers for AutoCAD, Civil 3D, Plant 3D, Navisworks and Revit: the team's installers are bundled unmodified, checked against a manifest of SHA-256 hashes, ticked when the program is found, run in their own windows, skipped in automatic updates.
- Approvals: requests are shown from the start of the app (not after the Claude sign-in check) and a tool now waits up to 60 seconds for the user's click instead of answering "waiting" at once; a denial is reported as such.
- Phase 10 (hardening): updates are authenticated (the release file is signed with the company's release key and the SHA-256 of Setup and the payload are checked before anything runs); replacing an existing file with the Office tools asks the user; the activity report and the knowledge pack conversion need the QC lead role; more credential shapes are scrubbed; unreviewed lessons are shown as hints; the activity log can be limited to metadata; scripts for the release key and for code signing; security review, runbook and quick start.
- Phase 9: self-learning. Offline queue (lessons and activity kept while the share is away are sent back), lesson curation (learn_pending, learn_review, generated LEARNED.md) and an activity summary, with review and activity windows for the QC lead; the activity report is now lead / admin only.
- GA check for piping plans (tested on the real client sample): line numbers with sizes and elevations, drawing references, matchlines and tier read; line numbers checked against the model, line list and P&ID text; the Navisworks runner now opens .nwc and .nwf files.
- Phase 8: GA drawing check. The model export now includes equipment with its bounding box; GA reader (tags, coordinates, elevations, scale, revision, north arrow); tags and coordinates checked against the model, tags against P&IDs and vendor data; tools ga_read and ga_check. Dimensions, nozzles and clearances are listed as not verified.
- Phase 7: P&ID check. Redrawn P&ID against the client's original on their text (line numbers, tags, labels, notes, horizontal and rotated), missing / changed / extra / moved items with sheet and zone; tools pid_read and pid_compare; the graphics are always reported as not verified.
- Phase 6: piping isometric check. Navisworks model export (hidden, on a copy) to a shared snapshot, isometric PDF reader, checks of identity, title block, BOM, coordinates and pipe lengths against the model and of the line list, PMS class and P&ID against the project inputs; tools model_export, model_summary, model_line, iso_read, iso_check, iso_check_folder; support map and tolerances in iso-rules.json.
- Phase 5: project inputs (inventory, coverage per QC type, searchable index with file and page / sheet and rows, line list read as data), client requirement packs where every rule has a source, the findings model and report (Excel + Markdown), QC checklists, six QC skills, 12 new tools (inputs_*, line_list_*, client_requirements, save_requirements, requirements_check, qc_checklist, qc_report_write); tags such as 2"-CD-60A07900-B400A-N-HS-017 are searchable by their parts.
- Phase 4: Setup (PecQcSetup.exe + payload.zip): readiness checks, per-user install without administrator rights, registration with Claude Code and Claude Desktop (config backed up first), skills copied without replacing a skill of the same name, Start-menu shortcut, uninstall that leaves nothing behind; update check from the shared updates folder with an Update now bar and a silent automatic update that keeps the choices of the first install; build-installer.ps1 and publish-release.ps1 (older version never replaces a newer one, latest.json written last).
- Phase 3: desktop app `PecQcAssistant.exe` (WPF): chat, first-run identity, QC project cards, Navisworks and project-inputs status lights, approval window, Knowledge and Guide pages, QC quick tasks with hints, settings with role.
- Phase 2 (real share): QC layout created on the company share (`Pec.Qc.Mcp.exe init-shared`), seed prompts and skills published, registry/lessons/activity/audit verified there with a gated integration test (`PEC_QC_SHARE_TEST`).
- Phase 2 (code): central user registry `users\<code>.json` and roles (qc-engineer, qc-lead, admin) enforced by the tools; new tools `users_list` and `set_user_role`; seed master prompt, quick tasks and platform skills; `publish-to-shared.ps1` and `make-office-defaults.ps1`; 130 tests.
- Phase 1: foundation. Solution `PEC_Qc.slnx` (Core, Mcp, Tests); the shared stack of the PEC assistants ported and renamed; QC project cards; QC system prompt and quick tasks; MCP server `pec-qc` with 34 tools; share probe that works on shares without delete; 118 tests.
- Phase 0: development plan (`DEVELOPMENT.md`), repository hygiene (`.gitignore`, leak scan, config template).
